# 초기 연결 진단 응답 뒤 키보드 초점 유지

2026-11-03 KST. 페이지를 연 직후 PC 조회를 시작하고 초기 `/api/diagnostics` 응답이 늦게 도착하면, pc.mjs가 패널 전체를 새 DOM으로 교체했다. 취소 버튼의 초점이 제거되어 Enter 취소와 완료 후 초점 복원이 끊길 수 있었다.

## 수정

연결 진단 성공·실패 시 패널을 교체하지 않고 `updateMode`로 연결 표시를 갱신한다. 버튼과 컨트롤러의 조회·취소 상태는 유지한다. 제공 서버 파일은 변경하지 않았다. 시험용 DOM의 `focus()`는 비활성 버튼을 무시하도록 보강했다.

## 검증

- 실제 pc.mjs 진입점을 실행하는 회귀시험에서 진단 응답을 조회 도중 전달했다. 수정 전 패널 동일성 assertion 실패, 수정 후 통과했다. 취소 버튼 초점·연결 표시 갱신·취소 후 늦은 결과 배제까지 확인한다.
- 외부 버튼에 있던 초점을 가져오지 않고 기존 조회 결과를 유지하는 시험을 추가했다.
- Windows·Node 24.19.0: 학생 59/59, 기존 단계 88/88 통과.
- 인앱 브라우저: 검증용 서버에서 진단 응답을 조회 시작 500ms 후 전달하고 실제 수집은 5초 지연했다. SDP 확인 불가→미연결 변경 후에도 취소 버튼 초점 유지, Enter 취소와 조회 버튼 복원을 확인했다. 재조회는 실제 7/7 정상이며 완료 후 조회 버튼으로 복원됐다.
- 지연은 검증용 실행에만 적용했으며 제출 소스에는 포함하지 않는다. 실제 다른 PC·다른 사람 검증은 아니다.

실행: on-client에서 `node student/run-local-pc.mjs` → `/student/pc` → PC 상태 조회. 정상 완료 시 결과와 조회 버튼 초점이 유지되고, 취소하면 현재 숫자를 지우며 늦은 응답을 표시하지 않아야 한다. 시험은 `node --test student/tests/*.test.mjs`로 실행한다.
