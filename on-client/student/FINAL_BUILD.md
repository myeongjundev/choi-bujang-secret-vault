## 핵심 기능과 선택

1. PC 자원 상태·추이: 제공 수집 기능을 재사용하고 단위·측정 시각·확인 불가를 명확히 표시한다.
2. 읽기 전용 네트워크·방화벽·Windows 기록: 설정을 바꾸지 않고 경고/오류 건수와 공격 탐지를 구분한다. SDP 연결 상태는 별도다.
3. 기존 사건 근거·조치 상태: 현재 사건 근거 연결과 ACK/관측 효과 구분을 유지하고 재조회·대기·실패를 표현한다.

포털에서 관제 대시보드형과 기본 포장·바로가기를 선택했다. 위 네 카드는 CPU·메모리·디스크·조회 상태, 아래는 추이·기록으로 계획한다. 선택 자체가 구현 완료는 아니다.

## 재실행과 전제

이 on-client 폴더에서 `npm start`, 브라우저 `http://127.0.0.1:5189/`로 기본 실행한다. 기본은 연결 없음이 맞다. 실행 창 Ctrl+C로 종료한 뒤 `npm run demo`로 예제를 따로 확인한다. 예제 앱 세 항목은 각각 allow/deny/challenge이고, 보안 기록 event-01 상세의 근거는 e-01, 규칙은 rule-01이다. `npm run check`와 `node --test student/tests/*.test.mjs`로 문법·합성 시험을 재현한다.

최신 0.2.14 ZIP와 현재 package.json에는 start/demo/check만 있고 package-app은 없다. PC 측정 API와 student/appearance.json 계약도 없다. 사용자는 별도 승인 host/포장 도구 안내를 아직 받지 않았다고 답했다. 완성본용 승인 환경과 해당 기능의 공식 제공 안내를 먼저 확인해야 한다. 없는 도구를 임의로 만들거나 승인 환경을 우회해 패키지 완료라고 쓰지 않는다.

이번 확인은 기본/예제 직접 실행이며 준비된 native 설정을 사용하는 실행 도구와 구분한다. 새 계정 연결·AI 앱 승인·보안 조치를 진행하지 않았다. 다른 사용자 실행과 설치형 앱 결과도 미확인이다.
