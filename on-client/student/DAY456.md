2026-10-28 KST의 공식 상황실 기준이다. 6일차가 과거 포장에서 **제출할 커밋 확인과 GitHub push**로 바뀌었다. 이번 과정에서 package-app·업데이트 도구·새 포장 스크립트는 실행하지 않는다. GitHub 소스 준비와 포털의 최종 제출은 구분한다.

## 4일차 화면

새 시작 주소는 http://127.0.0.1:5189/student/pc 다. [처음 실행 안내](START_HERE.md)를 따른다.

- PC 자원 상태, 연결·Windows 기록, 기존 사건 근거·조치의 세 동선을 먼저 보여 준다.
- CPU·메모리·디스크·조회 상태 네 카드에 조회 전/대기/확인 불가를 표시한다. 성공 시에만 실제 수치·단위·측정 시각을 표시한다.
- 최근 수동 조회의 CPU/메모리 %p, 표와 막대를 비교한다. 화면 메모리의 최근 20회이고 지속 감시나 원인 분석이 아니다.
- 서버가 멈추거나 취소되면 이전 숫자를 지우고 실패 원인과 다음 행동을 안내한다. 예시 값으로 대신하지 않는다.
- Tab·Shift+Tab·Enter로 실제 포커스 이동, 재조회와 취소를 확인했다. 상태 안내는 aria-live, 오류는 alert, 조회 영역은 aria-busy로 구분했다.
- 기본 데스크톱 화면에서 네 카드와 세 동선, 실제 조회·오류 화면의 시각 배치를 확인했다. 좁은 화면용 CSS는 포함하지만 모든 기기/화면 크기에서의 검증을 주장하지 않는다.

## 제공 파일과 학생 파일

제공 public/app.js·style.css·서버 원문은 수정하지 않았다. 학생 진입점이 고정된 대시보드 HTML/JS/CSS 경로를 추가하고, 기존 PC 표시/수집기를 재사용한다. 원래 보안 화면은 / 에 그대로 있다. 설치형 host에 자동 반영되거나 검증됐다고 쓰지 않는다.

PC 값은 실제 로컬 측정이다. SDP 예제를 선택해도 PC 측정은 예제 숫자가 아니며, SDP 자료에만 예제 표식을 붙인다. 경고/오류 건수는 침해 탐지, 방화벽 프로필 설정은 실제 차단 효과, 7/7 조회는 안전 판정이 아니다.

## 선언 버전 확인

공식 Node 24.19.0 Windows x64 ZIP을 공식 SHASUMS256과 대조하고 작업용 별도 폴더에서 사용했다.

~~~text
node-v24.19.0-win-x64.zip
SHA-256 57f71ab3652e797d84acddc79c81cc9ff1c6ddb2a1974cdb83f00fee9bff4c73
~~~

시스템 Node나 PATH를 변경하지 않았다. 해당 실행 파일로 학생 모듈 문법, 누적 51개 시험과 실제 일반 권한 PC 7항목 조회를 확인했다. 이전 문서의 Node 24.15.0 미일치 기록은 역사적 기록이며 이번 선언 버전 검증과 구분한다.

~~~powershell
node --version
node --check student/extension.mjs
node --check student/run-local-pc.mjs
node --check student/pc.mjs
node --test student/tests/*.test.mjs
~~~

## 5일차 재현

START_HERE.md에 준비·새 clone·실행 위치·시작 신호·버튼·종료·재시작·오류 대처와 수행 기록틀을 넣었다. 제출 커밋의 새 빈 경로 재현과, 다른 사람이 안내만 보고 수행한 결과는 별도로 기록한다. 에이전트가 같은 Windows PC에서 수행한 재현을 다른 사람이나 다른 PC의 확인으로 세지 않는다.

참여자가 준비됐다는 답변만으로 실행 성공으로 기록하지 않는다. 실제 실행자의 Node 버전·시작/조회/취소/종료 결과와 막힌 지점을 받아 확인한다. 개인 이름·키·토큰·주소 원문·이벤트 본문은 요청하거나 기록하지 않는다.

## 6일차 준비

기존 main의 통과본을 보존하고 codex/keshev-final-build 브랜치를 사용한다. 커밋 전에 포함 파일과 비밀값 검사를 확인하고 정상 push만 사용한다. 최종 저장소 주소·40자리 커밋·원격 확인·재현 결과를 제출 정보로 정리한다. --force를 쓰지 않는다. 실제 포털 접수와 최종 시연은 7일차 작업으로 남긴다.

## 현재 검증의 한계

실제 회사 서버 연결·AI 생성·보안 조치 집행, 다른 OS/기기, 설치형 host/포장은 미검증이다. 원래 13~22단계 통과는 서버의 코드 원문 검토이며 이번 로컬 실행과 별개다. 확인 불가를 정상·0건으로 바꾸지 않으며 실제 운영 보안 제품이라고 소개하지 않는다.
