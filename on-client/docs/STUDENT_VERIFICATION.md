# 학생 구현 검증 기록

## 13단계 · 2026-10-19

- 원본: 공식 alekov-starter-0.2.11. 기존 1~12단계 앱에 `on-client/`를 추가했다. 제공 서버·공통 UI·인증 코드는 수정하지 않았다.
- 구현: `student/extension.mjs`의 `renderIdentity`만 구현했다. 세 자원별 loading/ok/error와 connected/demo/disconnected/unknown을 구분하고 모든 문자열을 textContent로 표시한다. 매 호출 새 DOM을 반환하며 제공 UI의 replaceChildren으로 이전 신원이 제거된다.
- Node v24.15.0에서 `npm run check` 통과. 시작 틀 권장 버전 24.19.0과 다르지만 아래 실행은 실제로 확인했다.
- PC Chrome 예제 서버에서 사용자·기기·세션 값/ID, 예제 자료 표시, 세 메뉴 마우스 이동, Tab·Enter 및 방향키 이동, 다시 불러오기를 확인했다.
- 같은 페이지에서 예제 서버를 중단한 뒤 다시 불러오기를 눌렀다. 세 학생 영역에 연결 실패와 서버 오류 메시지가 나타났고 이전 연습 사용자·기기·세션 값이 사라졌다.
- 별도 학습 기록 저장소의 합성 DOM 시험 4개 통과: 사용자 A→B→오류 교체, 모든 기기/세션 상태, 자원별 loading/error와 모든 모드, HTML 모양 label/error의 문자 표시. 합성 입력은 운영 신원이나 연결 성공의 근거가 아니다.
- 실제 회사 엔진·실제 사용자 신원 연결은 미검증. 공식 AI 원문 판정은 제출 후 별도로 확인한다.

13단계 첫 원문 판정은 상태의 원래 코드 표시 누락으로 4/5였다. 한국어 설명 옆에 compliant/noncompliant/unknown 및 active/expired/revoked/unknown을 함께 표시하도록 보완했고, 합성 시험도 이 원래 코드 표시를 확인하도록 강화했다. 수정본을 재제출했으며 결과는 별도 확인한다.

## 14단계 · 2026-10-19

- `renderDecision`을 구현하고 13단계 함수를 보존했다. idle/loading/ok/error 분기, 한국어+원래 판정 코드, reason/checkedAt/appId, 예제·연결 모드를 표시한다.
- unknown과 예상 밖 판정은 확인 불가(unknown), 오류는 요청 실패이며 서버의 거부 판정과 다름을 표시한다. 실패·재조회 시 이전 허용/사유를 지운다.
- 합성 시험 2개 추가, 13단계 포함 전체 6개 통과. 네 판정·예상 밖 코드·HTML 모양 reason·허용→오류/idle/loading 전환을 확인했다.
- PC Chrome 예제 서버의 세 업무 앱으로 허용/거부/추가 확인, 키보드 Enter 요청, 이유/시각 표시를 확인했다. 다시 불러오기 후 이전 판정이 지워져 앱 선택 안내로 돌아왔다.
- 같은 페이지에서 서버 중단 후 앱 요청을 눌러 요청 실패와 거부 판정 구분을 확인했다. unknown 판정은 합성 입력으로 확인했으며 예제 서버 세 앱은 allow/deny/challenge를 반환한다.
- 실제 운영 앱 접속이나 추가 확인 절차는 실행하지 않았다. 원문 AI 판정은 별도로 확인한다.

## 15단계 · 2026-10-19

- `renderEvents`만 추가 구현했다. 전달받은 본인 범위 배열을 복사해 최신순 정렬하며, 기록 종류/업무 앱/접속 상태 선택 상자로 로컬 필터링한다. 추가 조회 요청은 보내지 않는다.
- 행의 `data-student-event-id`, 정확한 이름의 상세 버튼, 상세의 `data-student-event-detail`을 연결했다. ID·시각·종류·앱·요약, 근거/규칙 ID와 본문, 접속·세션·기기 세 상태의 한국어와 원래 값을 표시한다.
- 새 렌더링은 필터/목록/상세를 새로 만들고 오류 입력의 이전 data는 표시하지 않는다. 기록 없음·필터 결과 없음·조회 실패를 구분한다.
- 합성 시험 3개 추가(누계9): 원본 보존 정렬, 세 필터 결합, 근거·규칙·세 상태 상세, 새 데이터/빈 배열/오류 전환, HTML 모양 문자열.
- PC Chrome 예제 기록에서 세 필터 선택·Enter로 상세 열기·근거/규칙/세 상태·다시 불러오기 후 옛 상세 수 0을 확인했다. 다수·빈 목록·필터 결과 없음은 합성 데이터로 확인했다.
- 운영 다른 사용자 조회, 신규 XDR 탐지, 실제 조치를 수행하지 않았다. 공식 판정은 별도 확인한다.

## 16단계 · 2026-10-19

- `renderStatus`와 사건 상세의 미지원 조치 안내를 구현했다. 기기·현재 세션의 loading/빈 배열/error/ok, 알림의 자료·코드·메시지, 시간 초과, 직접 누르는 재조회 안내를 구분한다.
- 도움정보는 requestId/component/version/checkedAt/engine.mode/engine.code 여섯 필드만 선택해 표시·복사한다. 추가 필드는 제외하고 필드 안의 비밀값 모양 문자열도 가린다. 별도 점검 시각과 현재 연결 상태가 다를 수 있음을 표시한다.
- 학생 칸의 정확한 이름 「도움정보 복사」 버튼은 사용자 클릭 때만 clipboard API를 부른다. 정보가 없으면 비활성화하고 복사 실패도 성공과 다르게 표시한다. 자동 재조회·조치 요청을 추가하지 않았다.
- 사건의 supportedActions가 있을 때 상세 내부에 `<action> 미지원` 비활성 버튼과 연결 준비 중 안내를 표시한다. 빈 배열이면 버튼이 없으며 조치 전송 함수/리스너를 붙이지 않았다.
- 합성 시험 5개 추가, 누계14개 통과. 상태/시간 초과/복구/알림, 도움정보 필드 제한·추가 비밀 제외·클릭 전 복사0회·클릭 후1회·복사 실패, 미지원 버튼을 확인했다.
- PC Chrome 1920×855 예제 화면에서 기기·현재 세션·알림·도움정보 여섯 필드를 확인했다. 학생 복사 버튼 클릭 후 성공 문구를 확인했다. 브라우저 도구의 클립보드 읽기는 빈 배열이라 OS 클립보드 내용 자체는 확인하지 못했으며 필드 제한은 합성 clipboard 시험으로 검증했다.
- 서버 중단→수동 다시 불러오기에서 기기·세션 실패와 자료별 알림/재시도 안내, 기록 오류/옛 기록 제거를 확인했다. 서버 복구→직접 다시 불러오기에서 이전 연결 실패 문구가 사라지고 예제 기기/활성 세션으로 복구됐다.
- 실제 목록에는 지원 조치가 없으므로 비활성 조치 분기는 합성 데이터로만 확인했다. 운영 집행·운영 엔진 연결·악성코드 검사/치료 기능은 구현하거나 성공으로 표시하지 않았다.

실행: 이 폴더의 상위 `on-client`에서 `node src/server.mjs --demo` 후 http://127.0.0.1:5189/ 접속. 기본 연결 없음 확인은 `node src/server.mjs`. 종료는 실행 터미널의 Ctrl+C.

## 18단계 구현·로컬 검증 · 2026-10-24

- `student/extension.mjs`의 `renderExplanation`을 완성했다. 참고용 요약, 사건 ID, 인용 근거 ID와 본문, 규칙 ID와 본문, 항목별 확인 불가(unknown), 제안 없음의 이유와 제안의 사람 확인·미실행 상태를 표시한다.
- 현재 사건의 근거와 다른 ID·부분 인용·중복·근거/규칙 부족·지원되지 않는 제안·실행 주장은 성공으로 표시하지 않는다. 오류는 event:null이어도 먼저 표시하며, 안전한 code/message와 기록 보존 안내를 보여 준다.
- 매 호출 새 DOM을 반환한다. 제공 UI가 사건 선택/재조회/실패 뒤 이전 설명을 교체하며, 기존 세대 검사와 취소 제어가 늦은 응답을 버린다. 학생 함수에 요청·실행 버튼·자동 재시도를 추가하지 않았다.
- 별도 학습 기록 저장소의 신규 합성 시험 8개와 이전 회귀 19개, 총 27개 통과. Node 문법 검사 통과. 17단계 요약 시험의 성공 fixture를 완성된 공식 입력 계약으로 갱신했다.
- 실제 Chrome 합성 화면에서 사건 A→B, 근거 불일치, event:null 오류, 실행 주장, 초기화 다섯 경로를 확인했다. 별도 fixture 서버에는 AI·조치 API가 없다.
- 예제 앱의 AI 미구성(configured:false)을 확인한 뒤 설명 요청 1회에서 `ON_AI_PROVISIONING_PENDING`, 기존 보안 기록 보존을 실제 Chrome 화면에서 확인했다. 이후 업무 앱 allow와 다시 불러오기 뒤 설명 오류 제거도 확인했다. 실제 AI 생성은 미확인이다.
- 공식 18단계 판정은 이 커밋을 제출한 뒤 상황실에서 별도로 확인한다.
